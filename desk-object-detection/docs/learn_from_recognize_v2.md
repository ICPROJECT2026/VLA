# 从 recognize_v2.py 学到的思路

> recognize_v2.py 是「单模型 VLM 直接检测 + 识别 + 分类 + 定位」四合一的做法，
> 识别正确率高，但经常漏检。分析它和我们方案的区别，以及能借鉴什么。

## 0. recognize_v2.py 是什么

只用一个 Qwen2.5-VL-3B，一个 prompt 直接对整图输出：

```json
{"objects": [{"name": "...", "category": "垃圾/公共设施/个人物品/不确定",
              "reason": "...", "bbox": [左,上,右,下]}]}
```

其中 bbox 是 **0~1000 归一化整数坐标**。

## 1. 它的 prompt 设计（关键）

- **分类规则极详细**：垃圾=「明显被丢弃的包装袋、纸屑、烟头、空饮料容器等，必须结合摆放位置和状态，不能仅因为瓶子或纸张就判为垃圾」；公共设施=「垃圾桶、长椅等，垃圾桶本身不是垃圾」；个人物品=「仍在使用或有序存放的包、水杯、手机」；不确定=「看不清/无法判断，不要臆造」。
- **防漏**：「必须识别所有清晰可见的独立物体，同时列出垃圾和非垃圾，不能只输出一个物体」「逐行扫描全图，检查是否遗漏鼠标、键盘、手机、纸团等」「揉皱的废纸应考虑为垃圾，证据不足则标不确定」。
- **防误报**：「不存在的不要输出」「不要臆造物体」「键盘作为整体」。
- **强制依据**：每个物体都要给 `reason`（结合可见证据的简短理由）。
- **bbox 用 0~1000 归一化**（Qwen 原生 grounding 对齐格式）。
- **严格后校验**：category 必须是四类之一；bbox 必须是四个 0~1000 整数、左上<右下，否则报错。

## 2. 和我们思路的区别

| 维度 | recognize_v2.py | 我们（detect v0.x） |
|------|-----------------|---------------------|
| 定位 | Qwen 直接输出 bbox | YOLO 定位 |
| 检测+识别+分类 | 一个 prompt 全做 | 分阶段（YOLO → Qwen） |
| bbox 格式 | 0~1000 归一化（grounding 对齐） | 像素坐标 / 自由格式 |
| 分类标准 | 状态+位置（是否被丢弃） | 价值（可随意丢弃） |
| 防漏 | 逐行扫描 + 枚举提示 + 不能只报一个 | 靠 YOLO 召回 |
| 防误报 | 不存在的不要输出 + 不确定类 + reason | 基本没有 |
| 输出校验 | 严格（白名单 + bbox 合法性） | 宽松 |

## 3. 我们能学到的（5 点，按价值排序）

1. **bbox 用 0~1000 归一化**（最重要）——这正是我们早前讨论的「grounding 格式（想法 C）」。Qwen 训练对齐的就是 0~1000 坐标，比像素坐标/自由格式**位置更准、更稳**。我们之前一直用像素坐标，是位置漂移的原因之一。

2. **详细分类规则 + 正负例**——它把「怎么判垃圾」写得很细（结合位置状态、垃圾桶不是垃圾、瓶子纸张不必然垃圾）。不管分类标准是「状态」还是「价值」，这种「细规则 + 正负例」的写法都值得照搬。

3. **防漏 prompt 技巧**——「不能只输出一个物体」「逐行扫描检查遗漏」「枚举可能物体」——这正是我们「检测求准、不漏」的落地写法。

4. **防误报 prompt 技巧**——「不存在的不要输出」「不要臆造」+ **reason 强制给依据** + **不确定类**——正好对应「检测求准、不多报」。

5. **严格后校验**——category 白名单 + bbox 合法性校验，模型输出不对就显式报错，而不是静默接受垃圾输出。

## 4. 它「经常漏检」的原因（我们不要重蹈覆辙）

1. **让 Qwen 做检测**：检测/定位是 3B 的弱项，这正是我们踩过的坑（v0.2 结构化扫描只报 2 个、v0.4 整图被带偏）。它让 Qwen 既检测又识别，检测环节自然漏。
2. **「清晰可见」限定**：prompt 写「识别清晰可见的物体」，天然漏掉低对比、小尺寸、模糊的纸团。
3. **复杂 prompt 3B 未必遵循**：「逐行扫描」对 3B 是引导而非真扫描，可能跳步。

**核心洞察**：recognize_v2.py 的「漏检」根因是「让 Qwen 干它不擅长的检测」；而我们用 YOLO 解决了检测，所以**「YOLO 检测 + Qwen 识别」的架构方向是对的**。我们要做的，是把 recognize_v2.py 的「识别/分类 prompt 精华」搬到 Qwen 识别环节，而不是放弃我们的架构。

## 5. 结合到我们方案的建议

1. **Qwen 识别环节改用 0~1000 归一化坐标**（如果让 Qwen 输出框的话），或至少让 YOLO 框统一换算成 0~1000 再和 Qwen 交互；
2. **把详细分类规则 + reason + 不确定类**搬进我们的识别 prompt（用「价值标准」重写规则即可）；
3. **保留「不存在的不要输出」「不要臆造」**，配合我们的 IoU+name 去重，进一步压低误报；
4. **YOLO 定位保持不变**——它已经证明能框出全部 4 个物体、位置准，这是 recognize_v2.py 做不到的。
