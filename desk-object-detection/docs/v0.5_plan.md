# v0.5 方案：YOLO 定位 + 精细化识别（借鉴 recognize_v2.py）

> 目标：继承 v0.4 的「YOLO 定位 + 局部图逐框 + 规则去重」架构，
> 把 recognize_v2.py 的 prompt 精华（详细规则、reason、不确定类、防臆造）融入 Qwen 识别环节。

## 0. 定位

- 检测（定位）：继续用 YOLO-World——已证明能框出全部物体、位置准。
- 识别（命名/分类）：Qwen 局部图逐框，但 prompt 从「简单」升级为「精细化」。

## 1. 相比 v0.4 的改进

| | v0.4 | v0.5 |
|--|------|------|
| 识别 prompt | 只问 name + category | name + category + reason |
| 分类规则 | 一句话 | 详细规则 + 正负例（价值标准） |
| 不确定处理 | name 填 unknown | 显式「不确定」类 + unknown |
| 防臆造 | 无 | 「不要臆造物体」 |
| bbox 输出 | 像素坐标 | 统一 0~1000 归一化 + 像素坐标 |
| 结果校验 | 宽松 | 严格（类别白名单 + bbox 合法性） |

## 2. 流程（继承 v0.4 改版）

```
阶段 A：YOLO-World 定位 → 候选框（像素坐标，conf 过滤）
   │
阶段 B：对每个框裁剪局部图，逐框识别
         Qwen 输出 {name, category, reason}
   │
阶段 C：规则去重（IoU 高 且 name 相同 → 合并，保留置信度最高）
         （name=unknown 不参与合并）
   │
输出 objects（bbox 同时给像素 + 0~1000 归一化）
```

## 3. 核心：新的识别 prompt（草案）

```
请识别这张裁剪图中唯一的物品。

判断规则：
1. 先判断图里是「独立物品」还是「背景/桌面纹理/阴影」——若是背景，name 填 unknown、category 填 不确定。
2. name：物品名称（中文），认不出填 unknown。
3. category（按价值标准）：
   - 垃圾：价值低、可随意丢弃的物品（矿泉水瓶、纸团、包装袋、纸巾、瓶盖等，即使完好也算垃圾）
   - 公共物品：图书馆等公共场所供公众共同使用的物品（键盘、鼠标、显示器、饮水机、打印机、桌椅等）
   - 私人物品：个人私有的物品
   - 不确定：看不清或无法判断
4. reason：结合可见证据的简短理由（你看到了什么颜色/形状/纹理特征）。

不要臆造物体；没有清晰物体就输出不确定。

只输出一个 JSON 对象，不要输出任何其他文字、解释或 Markdown 代码块。格式：
{"name":"物品名称或unknown","category":"垃圾/公共物品/私人物品/不确定中的一个","reason":"简短理由"}
```

## 4. 去重规则微调

- 基本规则不变：IoU 高（>0.5）且 name 相同 → 合并，保留置信度最高的框。
- 新增：**name=unknown 的框不参与合并**（两个 unknown 可能是不同物体，不能因为重叠就删掉）。

## 5. 我的思考

1. **架构不动，只换识别 prompt**：YOLO 已经解决了「检测弱」这个 recognize_v2.py 的漏检根因，我们只需要把它的「识别质量」搬过来，两者互补。
2. **reason 的价值**：强制模型给依据，既能防臆造，又能在出错时人工核查（比如「本优」这种，reason 会暴露它是读到了瓶身文字）。
3. **不确定类的价值**：给模型一个「看不清就说不知道」的出口，比硬猜成「袜子」更诚实、更可控。
4. **bbox 0~1000**：统一坐标口径，和 recognize_v2.py / Qwen grounding 对齐，方便后续对比和扩展。

## 6. 我的困惑

1. **reason 会加长输出**：逐框识别时每个框多一个 reason，`max_new_tokens` 要预留；会不会拖慢、或让 3B 更易输出错乱？

2. **「不确定」类会让去重变复杂**：如果键盘的 3 个重复框里，有的被识别成「不确定」，就不会和其他「键盘」合并，导致本该去重却去不掉。怎么办？

3. **分类标准仍是「价值」而非「状态」**：recognize_v2.py 用「是否被丢弃」判垃圾，我们用「价值低」判垃圾——按价值标准，「满的矿泉水」也是垃圾，但「完整放在桌上的矿泉水」模型可能倾向判私人物品。这个口径需要你确认：**价值标准要不要在 prompt 里强调「与摆放状态无关」？**

4. **bbox 0~1000 在我们架构里意义有限**：因为框是 YOLO 给的（像素坐标），Qwen 只出 name/category，0~1000 主要是「输出格式统一」，并不会改善定位本身。是否值得为此改动输出格式？
