# v0.4 方案：YOLO 定位 + 整图/局部图成对识别 + 规则去重

> 目标：保留 YOLO-World 定位，把 Qwen 的输入改成「整图 + 单张局部图」成对给，
> 一次只处理一个框，解决「图太多」和「编号对应」两个问题；去重交给代码规则，不让 Qwen 做。

## 0. 方案概述

- **阶段 A**：YOLO-World 定位，得到候选框（conf 过滤，不做 IoU 硬删）。
- **阶段 B**：对每个候选框，**成对输入「整图 + 该框局部图」**，Qwen 识别局部图里的物体（name + category）。
- **阶段 C**：代码后处理去重——IoU 高的框若 name 相同则合并（**以小框为标准**）。

## 1. 相比 v0.3 的改进

| | v0.3 | v0.4 |
|--|------|------|
| Qwen 输入 | N 张局部图打包 | 整图 + 单张局部图（成对） |
| 图数量 | 6 张一起 | 每次 2 张 |
| 顺序对应 | 靠图片顺序，易乱 | 天然明确（每次只一个框） |
| 画框/编号 | 无 | 不需要 |
| 去重 | 无 | 代码规则（IoU + name） |

## 2. 流程

```
YOLO 定位 → N 个候选框
   │
   ▼
for 每个框 i：
   输入 = 整图 + 框 i 的局部裁剪图
   Qwen 输出 = {name, category}
   │
   ▼
得到 N 个 {bbox, name, category}
   │
   ▼
后处理去重：IoU 高的框对，若 name 相同 → 合并（保留小框）
   │
   ▼
输出最终 objects
```

## 3. 关键设计

### 3.1 整图 + 单局部图成对输入

- 每次给 Qwen **2 张图**：第一张整图（提供全局上下文），第二张是当前框的放大裁剪图。
- prompt 说明：「第一张是整图；第二张是整图中某个候选物体的放大图。请识别第二张放大图里的物体。」
- **不画框、不编号**——每次只有一张局部图，对应关系天然明确。

### 3.2 Qwen 输出（不做去重）

```json
{"name": "键盘", "category": "公共物品"}
```

- 只输出 name + category。

### 3.3 去重规则（代码后处理，小框优先）

- 两两计算 IoU，高于阈值（如 0.5）的框对视为「重叠」；
- **IoU 高 且 Qwen 识别出的 name 相同** → 判定为同一物体，合并，**保留小的框**；
- **IoU 高 但 name 不同** → 判定为遮挡的不同物体，都保留。

## 4. 我的思考

1. **成对输入一举两得**：同时解决「图太多」和「编号对应」——每次只 2 张图，对应天然明确。
2. **整图 + 局部**：整图给「在哪、和谁挨着」的上下文，局部图给「是什么」的细节，弥补 v0.3 丢上下文的缺陷。
3. **规则去重（IoU + name）**：比纯几何 IoU 聪明（能区分「重复」和「遮挡重叠」），又比让 Qwen 做空间推理去重简单、可解释、可控。
4. **小框优先合理**：YOLO 对重叠区域常给出偏大的框（过度扩展），小框往往更贴合物体本体。

## 5. 我的困惑

1. **逐框 = N 次调用，超「3 轮」预算**：N=6 就是 6 次 Qwen 调用，比之前「最多 3 轮」多。需要你确认接受这个时间代价（正确性优先）。

2. **「小框」的标准**：是「面积最小」，还是「最贴合物体」？面积最小的框可能裁掉物体边缘（比如键盘的一部分），而 ground truth 的键盘框并不等于三个里最小的那个。是否要改成「置信度最高的框」或「加权平均」？

3. **name 的一致性**：合并依赖「Qwen 识别出的 name 相同」，但同一个键盘的 3 个框，Qwen 可能分别识别成「键盘」「笔记本电脑」「遥控器」——name 不一致就合并不了。是否需要 name 归一化 / 模糊匹配？

4. **整图重复给 N 次**：每个框都带一次整图，整图被重复编码 N 次，冗余但必要（提供上下文）。是否值得？（我倾向值得，但想听你的意见）

5. **遮挡物体合并的边界**：两个重叠的物体（瓶子压键盘），IoU 高但 name 不同 → 保留两个。但如果 Qwen 把「被压住的键盘局部」也识别成「键盘」，会和另一个「键盘」框误合并（依赖 Qwen 识别稳定性）。
