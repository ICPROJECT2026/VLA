# 遮挡场景下的定位与去重 — 想法与困惑

> 背景：当前 6.jpeg 中物体重叠少，IoU 去重（6→4）有效。
> 担忧：后续测试可能随意摆放、物体相互堆叠遮挡，此时几何去重可能误删真实物体。

## 1. 核心矛盾

IoU / NMS 去重的隐含假设是：**「框重叠 = 同一个物体被重复检测」**。

但遮挡时，「框重叠」的含义变了：**两个不同物体在画面上前后重叠，它们的框自然也重叠**。

而这两个情况在几何上**长得一模一样**——都是一堆重叠的框。仅凭 2D 框，无法区分：

- 「键盘被重复框了 3 次」（该合并）
- 「瓶子压在键盘上，两个框部分重叠」（该保留两个）

**这是信息层面的局限，不是调参能根本解决的。**

## 2. 遮挡对 YOLO 定位的影响

| 表现 | 说明 |
|------|------|
| 框不全 | 只框出可见部分，框比真实物体小 |
| 漏检 | 遮挡严重时，被挡物体直接检测不到 |
| 粘连 | 两个相邻/重叠物体被框成一个大框 |
| 误框 | 把两个物体的一部分合成一个错误的框 |

更麻烦的是：**YOLO 内部本身就有 NMS**（predict 时的后处理），重叠的不同物体可能已经在 YOLO 内部被误删了。我再额外加一层 IoU 去重，等于雪上加霜。

## 3. 遮挡时 IoU 去重的失效场景

举例：瓶子放在键盘前面。

- 瓶子的框 与 键盘的框 有部分重叠，IoU 可能 > 0.5；
- 我的去重逻辑会把「置信度低的那一个」删掉 → **误删一个真实物体**；
- 结果从「应该保留 4 个」变成「只保留 3 个」，召回下降，正是用户最不想看到的。

## 4. 可能的应对思路

### 4.1 降低 IoU 阈值（两难）

- 阈值降到 0.3，能少误删重叠的不同物体；
- 但真正的重复框（键盘 3 个）也可能漏合并。
- 本质是「重复」和「遮挡重叠」在几何上不可分，调阈值只是左右摇摆。

### 4.2 Soft-NMS（降权而非硬删）

- 重叠框不直接删，而是降低其置信度；
- 重叠的不同物体若置信度都够高，可能都保留；
- 但仍无法真正区分「重复」vs「遮挡」，只是把硬伤变软伤。

### 4.3 语义辅助（用标签区分）

- 之前说「不看标签」；但遮挡时，两个重叠框若标签不同（keyboard vs bottle），可能暗示是不同物体；
- 问题是 YOLO 默认标签本身不可靠（把瓶子标成 clock），参考价值有限。

### 4.4 把「去重」交给 Qwen（几何转语义）

- YOLO 只负责**宽松地多给候选框**（不去重或轻度去重）；
- Qwen 对每个框裁剪，判断：①这是什么物体 ②是否被遮挡/不完整 ③是否和别的框是同一物体；
- 把「是否合并/删除」的判断从几何 IoU 转移到 Qwen 的语义理解。
- 这是我倾向的方向：**去重应该靠「看懂」，而不是靠「算面积重叠」**。

### 4.5 两阶段确认

- 阶段 A：YOLO 给候选框（conf 调低，多给）；
- 阶段 B：Qwen 逐框裁剪识别，同时输出「是否独立完整物体」；
- 阶段 C：依据 Qwen 结果做最终去重。

## 5. 我的困惑

1. **几何去重的根本局限**：2D 框不携带「深度/前后」信息，遮挡重叠和重复框在几何上不可分。这是否意味着「纯几何去重」在遮挡场景必然失效，只能靠语义去重？

2. **Qwen 能否可靠判断遮挡**：3B 模型看到一张「被遮了一半的瓶子」的裁剪图，能否稳定说出「这是被遮挡的瓶子」？还是会把「半个瓶子」当成别的东西、或当成完整瓶子？

3. **YOLO 内部 NMS 我们控制不了**：它可能已经误删了重叠物体。我们只能通过 `iou` / `conf` 参数调，但无法关闭。是否需要考虑换检测器，或用更低层的方式拿原始框？

4. **「检测求准」在遮挡下的口径**：被遮挡的物体，框应该框「可见部分」还是「推测的完整范围」？「被挡一半的瓶子」算不算一个「要检出的物体」？这个口径需要你提前定，否则遮挡场景的 ground truth 无法标注。

## 6. 我倾向的方向

1. **去重轻量化**：遮挡场景下，YOLO 只做「conf 过滤」，**尽量少用 IoU 硬删**，把重叠判断留给 Qwen；
2. **Qwen 语义去重**：对每个候选框裁剪，让 Qwen 输出「名称 + 类别 + 是否完整/被遮挡」，据此合并或保留；
3. **口径先行**：遮挡物体的框和「算不算检出」的标准先定下来，再谈算法。
