# 多图方案与 Qwen 3B 多图能力 — 想法与困惑

> 背景：1.jpg 上暴露两个识别问题——[7] 椅子局部被认成键盘、[8] 盒子+半鼠标被认成鼠标。
> 根因是「裁剪图信息不完整 + 模型脑补」。多角度/多图理论上能补信息，
> 但我对 Qwen 3B 处理多图的能力有所怀疑。这里记录想法和困惑。

## 1. 我们对 Qwen 3B 多图能力的实验证据（回顾）

我们其实已经做了三次「多图/图+结构化信息」的实验，全部失败：

| 实验 | 输入形式 | 结果 | 结论 |
|------|----------|------|------|
| v0.3 | 6 张局部图打包 | 只输出 2 个，顺序乱 | 多图数量/顺序处理失败 |
| v0.4 初版 | 整图 + 1 局部图 | 被整图带偏（玻璃瓶泛滥） | 多图注意力分配失败 |
| test.py | 整图 + 6 个坐标文本 | 编号错位（玻璃瓶、纸巾错位） | 图 + 坐标对应失败 |

三次实验，三种多图形式，**没有一个能可靠工作**。这不是偶然，而是指向一个结论：
**Qwen 3B 无法可靠处理「多张图之间、或图与结构化信息（坐标）之间的对应关系」。**

所以用户对「多角度图片」方案的怀疑，是有充分实验依据的。

## 2. 我的想法

1. **多图方案在 3B 上可行性很低**：上面三次失败已经证明。多角度图片本质上还是「多图 + 对应」，大概率重蹈覆辙（顺序乱、被带偏、错位）。

2. **应优先「单图优化」，而不是「加图」**：
   - **优化 YOLO 框**：让框尽量贴合完整物体，减少「框到碎片」（[7] 椅子一角）和「框到混合物」（[8] 盒子+鼠标）的情况；
   - **裁剪加 padding / 扩大上下文**：单张图里多带一点周围环境，让椅子局部不再是孤立的「黑色矩形」；
   - **恢复「不确定/不完整」出口**：让模型能输出「这是物体的局部」「被遮挡」「不完整」，而不是硬猜成键盘/鼠标。

3. **多图/多角度留到大模型再试**：如果换 Qwen2.5-VL-7B/72B，多图能力可能达标，届时再评估多角度方案。

## 3. 我的困惑

1. **多图能力弱，是 3B 特有还是 VLM 通病？**
   如果是 3B 特有，换 7B/72B 就能用多图；如果是通病（VLM 对多图对应天然弱），那多图这条路本身就要放弃。我目前没有足够证据判断这一点。

2. **「信息不完整」的根因，是框不准，还是裁剪方式？**
   [7] 框到椅子一角、[8] 框到盒子+鼠标——如果 YOLO 框更准（框住完整椅子、框住完整盒子或完整鼠标），是不是「信息不完整」的问题就消失了，根本不需要多图？

3. **「不确定/不完整」出口能解决脑补吗？**
   之前我们搁置了「不确定」类。如果恢复它，模型面对「半个鼠标」时会老实说「被遮挡/不完整」，还是仍然硬猜？3B 有没有这个「自知之明」？

4. **单图方案的天花板在哪？**
   纯单张裁剪图，对「碎片/混合物/低对比」场景，3B 的识别极限是什么？会不会优化到一定程度后，还是要靠多图或更大模型才能突破？

## 4. 我的初步倾向

- 暂不上多图/多角度（3B 证据不支持）；
- 先做「单图三件套」：优化框贴合 + 裁剪加 padding + 恢复「不确定」出口；
- 多图方案记入待办，等换大模型时再验证。
